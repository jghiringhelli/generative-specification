# The GitHub Copilot route for scripted experiment runs: what the documentation says (2026-10-09)

Status: research note, no experiment run. Written to decide how the second PC runs the experiments through a Copilot subscription without API keys. **The author has no Copilot account and ran no model call.** Everything below is from official pages and from the Copilot CLI's own offline help text.

Tags: **[V]** read on an official page on 2026-10-09 (URL given). **[V*]** confirmed by running the CLI's own `--help` / `help` text offline in the container image `fx1-linux-copilot` (CLI 1.0.94, no login, no model call). **[S]** secondary source (URL). **[U]** unverified or inferred. Quotation marks are verbatim.

## 1. Three corrections to what was assumed before

1. **Copilot is no longer billed by premium requests for most plans; it is metered by tokens.** [V] https://docs.github.com/en/copilot/concepts/billing/copilot-requests says: "This article only applies to Copilot Pro and Copilot Pro+ subscribers on an existing annual plan who remained on legacy premium request-based billing after June 1, 2026." The current model is GitHub AI Credits, 1 credit = $0.01, priced per token at each model's rate [V] https://docs.github.com/copilot/concepts/billing/usage-based-billing-for-individuals (read via a summarizing fetch; the 1-credit figure is also in [S] https://github.blog/news-insights/company-news/github-copilot-is-moving-to-usage-based-billing/). Consequence: a cap "in premium requests" only means something on a legacy annual plan. The harness therefore keeps five caps (calls, wall-clock, premium requests, AI credits, dollars) and JC sets the ones his plan makes meaningful.
2. **"Copilot gives no token counts" is out of date, in principle.** The CLI exports OpenTelemetry. [V*] `copilot help monitoring`: "The CLI can export traces and metrics via OpenTelemetry (OTel), giving you visibility into agent interactions, LLM calls, tool executions, and token usage"; `COPILOT_OTEL_FILE_EXPORTER_PATH` "Write all signals to this file as JSON-lines"; metrics include `gen_ai.client.inference.usage.input_tokens`, `...output_tokens`, `...cache_read.input_tokens`, `...cache_write.input_tokens`; "Spans carry attributes such as model name, token counts, durations, costs, and error info." Also `/usage` shows per-model token totals [S, from the research pass; the slash-command page was not opened], and the Copilot SDK emits typed usage events [S] https://docs.github.com/en/copilot/how-tos/copilot-sdk/features/usage-and-billing. **Not verified in practice:** whether `-p` mode writes the OTel file with token attributes, and whether the numbers are right (a known SDK issue reports duplicated usage in some exports [S] https://github.com/github/copilot-sdk/issues/2774). The harness captures the file and parses defensively; `adapter-probe.mjs --live` reports whether tokens were captured. Treat any token number as indicative until compared with the billing page.
3. **The registration's "formulas tag" does not exist, and the thing earlier called a lightweight tag is a branch.** `git tag --list` and `git ls-remote --tags origin` print nothing in the protocol repository; `formulas-2026-10-05` is a branch (`git cat-file -t formulas-2026-10-05` prints `commit` because every ref does). The gate (`experiments/fx1/harness/gate-check.mjs`) therefore finds no frozen formulas tag and no `prereg/FX-1-v*` tag.

## 3. Models selectable in the CLI (exact ids)

[V] https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference, "Supported models" (raw markdown read 2026-10-09): `claude-sonnet-5.5` (default), `gpt-5.4`, `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6-luna`, `claude-opus-5.5`, `claude-haiku-5.5`, `claude-haiku-4.5`, `gpt-5.3-codex`, `gemini-3.7-flash`, `gemini-3.8-flash`. The wider supported-models page [V] (https://docs.github.com/en/copilot/reference/ai-models/supported-models) also names Anthropic (Fable 5, Fable 5.1, Opus 4.8, Opus 5, Sonnet 4.6, Sonnet 5), OpenAI (GPT-5 mini, 5.4 mini/nano, 5.5, 5.6 Luna/Sol/Terra, 6 Astra/Luna/Sol), Google (Gemini 3.7 and 3.8 Flash), xAI (Grok 4.5 to 4.7), Moonshot Kimi K3 and a Microsoft model, **without CLI ids**; their ids are probably lower-case hyphenated [U]. The ids that **your account can call** depend on plan and organization policy; the CLI has no documented non-interactive list command [U], so `models-discover.mjs` pings each candidate once and records which answer. A GitHub issue says the CLI list can omit organization-enabled models that VS Code shows [S] https://github.com/github/copilot-cli/issues/1703. Record the id exactly as the CLI accepts it; the CLI returns no dated snapshot id in the pages read [U], so "model drift" is detected only by the served-model string the OTel file reports and by the date.

## 4. Metering, caps and what to read

- Plans and monthly AI-credit allowances [V] (docs plans page, via the research pass): Pro $10 = 1,500 credits; Pro+ $39 = 7,000; Max $100 = 20,000; Business $19 per seat = 1,900 pooled; Enterprise $39 per seat = 3,900 pooled. The April blog post gives other figures ("Pro includes $10"), so **read your own plan page**. **A 30-run development batch at the ~$2 per run seen in the Claude development loop is about 6,000 credits**: far above a Pro allowance. JC's "privileged" subscription may differ; he must read it before Phase 3.
- Per-model prices: [V] https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing (read 2026-10-09; 1 AI credit = $0.01; USD per 1M tokens input / cached input / output, default-context rows, for example gpt-5.4 2.50 / 0.25 / 15.00, gpt-6.1-sol 2.00 / 0.10 / 10.00, claude-sonnet-5.5 2.00 / 0.10 / 10.00, claude-opus-5.5 4.00 / 0.20 / 20.00, gemini-3.8-flash 0.75 / 0.075 / 3.75; a long-context tier costs more). They are copied into `experiments/fx1/harness/models.json`.
- Legacy request plans only: "Each prompt to Copilot CLI uses **one premium request** with the default model" and "only the prompts you send count as premium requests; actions Copilot takes autonomously to complete your task, such as tool calls, do not" [V] https://docs.github.com/en/copilot/concepts/billing/copilot-requests. Multipliers per model: [U] the page links a "Model multipliers for annual plans on request-based billing (legacy)" table that was not read; `models.json` leaves them empty, and the harness then counts 1 per prompt and flags it.
- Where to read usage: Settings, Billing and licensing, Metered usage, Copilot, with a CSV [S]; a billing usage REST API exists [S] https://docs.github.com/en/rest/billing/usage. Not opened.
- The harness cannot see the bill. It writes `ledger.jsonl` (calls, duration, tokens when captured) and the person compares it with the usage page after each phase (`spend.csv`).

## 5. Rate limits and terms (read, not interpreted)

- [V] https://docs.github.com/en/copilot/concepts/rate-limits: "Rate limiting is a mechanism used to control the number of requests a user or application can make in a given time period"; "If you are making frequent or automated requests (for example, rapid-fire completions or large-scale usage), consider adjusting your usage pattern." No numbers, nothing on parallel use. [S] session and weekly limits introduced "to control for parallelized, long-trajectory requests" (GitHub's April 2026 individual-plan post); users report 429 messages ("you've exceeded your 5 hour session limits", `user_weekly_rate_limited`): https://github.com/orgs/community/discussions/192485 , https://github.com/github/copilot-cli/issues/2742. **Expect limits on hundreds of unattended cells; run serially (parallel 1) and back off on 429.** [U] sizes.
- [V] GitHub Acceptable Use Policies, https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies : prohibit "using our servers for any form of excessive automated bulk activity, to place undue burden on our servers through automated means" and reserve the right to suspend an account whose usage is "significantly excessive in relation to other users of similar features".
- [V] GitHub Terms of Service (https://docs.github.com/en/site-policy/github-terms/github-terms-of-service), as quoted by the research pass: "Accounts registered by 'bots' or other automated methods are not permitted"; "Your login may only be used by one person"; "You may not share API tokens to exceed GitHub's rate limitations"; inputs and outputs are used for training "unless (a) you opt out through your account settings, or (b) your use of the Service is governed by a GitHub Customer Agreement". Business and Enterprise are under the GitHub Generative AI Services Terms.
- **What I found: the CLI's `-p` mode and the token variables are documented, supported ways to script Copilot; I found no sentence that permits or forbids bulk evaluation runs on an individual plan, and nothing about benchmarking or about using outputs to study other models.** I did not read the Additional Products terms or the Generative AI Services Terms in full. **JC must check:** (1) his plan type and whether it is individual or Business/Enterprise (different terms); (2) the AI-credit allowance, any overage budget, and the policy toggles (CLI enabled; each vendor's model enabled; `permissions.disableBypassPermissionsMode` would block `--allow-all-tools`); (3) the Copilot setting that stops his content being used for training (the fixture briefs and prompts leave the machine); (4) that a few hundred agent sessions per week through one login is acceptable to him: if in doubt, ask GitHub support in writing before Phase 3, because the penalty named in the AUP is suspension of the account.
