# Critic 2: fairness and construct validity (E2E-1 draft rev 1, REVIEW-SURFACE-SPEC)

1. Substrate arms receive extra prompt content by construction (BLOCKER). Section 2 rule 1. The substrate "may carry instructions (an auto-loaded file)". An auto-loaded sentinel and rules file is per-session text the model reads every session, so the "prompt identical" claim is false in effect. The 2x2 therefore does not separate prompt from substrate; it crosses "user text" with "user text plus a second, GS-authored prompt". Section 12 admits this but the decision table (g, h, i) still interprets the interaction as "substrate compensates for a weak prompt". Fix: add an arm with the substrate's instructions flattened into the prompt and no persistent structure (SDX-1 A3), or drop rows g to i and word the factor as "GS bundle present/absent".

2. Arm X still carries more than the practitioner's natural prompt (MAJOR). Section 2 rule 2 uses A6 (natural, unconstrained) and allows the agent to create README, notes, tests. If the expert asks for notes or ADRs, X builds a partial substrate, and the X+S minus X contrast shrinks toward zero for reasons unrelated to GS value. That is a valid rival, but then the "leak check M1 against the named elements" cannot be required to be zero (rule 2 says leak-checked, section 8 says "leak in arm X" is INVALID-DESIGN) while the same section allows persistence. These contradict. Fix: choose before freeze: A6 with M1 descriptive only (as SDX-1 did), or A5. Remove the INVALID trigger for X leaks if A6.

3. Practitioner independence is unenforceable as written (MAJOR). Section 2 rule 2, section 14.3. The practitioner reads the GS-free spec but the projects, traps and substrate are authored by the GS side; the practitioner sees the task and project. Nothing stops the prompt being tuned to the traps (if shown the change list) or, inversely, hidden from it so the prompt cannot address the invariants the traps break. State what the practitioner may see (spec yes, change list no) and apply symmetrically to the substrate builder, who also must not see traps. Section 2 rule 3 says the builder has not seen the traps, but the GS side that authored the conformance checker and formula presumably saw P4 trap classes; declare that.

4. Trap authoring is circular for the P-REG outcome (MAJOR). Section 4, section 6. Traps are "the natural implementation breaks a rule carried since phase 1". Rules that the substrate records (criterion ids, invariants in decision records) are the ones a trap can be written against; a trap whose rule is stated in the spec the substrate indexes favours the arm that re-reads it. Project 2 by a skeptic helps, but the "veto for ambiguity" by the GS side is a lever. Fix: classify each trap by whether its rule is in the spec text (visible to all arms) or only implicit; report P-REG by class; give the veto log to the independent reviewer; skeptic's traps frozen before the GS side sees them.

5. Setup and upkeep cost counted unevenly (MAJOR). Section 6. Setup hours of the GS builder are one-off, amortized over phase 2; the practitioner's prompt-authoring hours are also in "human hours" but substrate maintenance by JC (ratification, lock updates, baseline decisions) in the loop is not specified. Conformance fixing and any human ratification in substrate arms are human work arms X and N never get. Also amortizing over one project's 12 to 16 changes inflates the per-change cost. Fix: record every human intervention per arm, price at one rate, report amortization at several horizons (12, 100, 1000 changes) with no verdict on the horizon.

6. Factor confounding through retry and gate behaviour (MAJOR). Sections 2.4, 4. "Retry rule never conditioned on the arm's own tests" but substrate arms have hooks that block commits; a blocked commit is an in-session retry other arms do not have. The cap per session is equal, but effective work per token differs. Also the scored state is "after the last attempt", so a gate that blocks and leaves the tree failing is scored. Fix: define the scored state as the last tree state at cap or at the model's own stop, and report block counts as a mediator; pre-register how a blocked session that ends uncommitted is scored.

7. Blinding is nominal (MAJOR). Section 7. JC checks "through a neutral interface", but he wrote the method and projects; behaviours differ by arm in style, error wording, logging; the sample includes "every use case where suite and judge disagree", which is selected after seeing automated results, contradicting "before he sees any automated result". Fix: draw the disagreement set by an assistant, show it only after the first pass; have the non-GS second checker do the primary pass on a third, JC the second; report agreement and a blinding-guess test (checker guesses arm).

8. Judges not independent of the outcome definition (MINOR). Section 6. Judged maintainability and spec-conformance are given repository, which contains the substrate in S arms; "blind" pairwise comparison is impossible when a sentinel and decision tree are visible. Fix: give judges the source tree with substrate paths stripped and say so; keep as secondary (already).

9. Positive control and E2E-0 pilot are tuned on the study arms (MINOR). Section 8. Adding "harder traps before freezing" when the weaker arm is at 95 percent selects traps that the naive arms fail, i.e. headroom is engineered against the arm that decides; if pilot finds weaker arm below 95 for the wrong arm, nothing is added. Fix: specify that trap hardening uses arm N alone (floor arm) and not the contrast, and log trap changes.

10. Equal-tooling rules are not enforceable with own CLIs (MINOR). Section 5. Three vendor CLIs differ in context management, default instructions, auto-loaded files (CLAUDE.md, AGENTS.md, GEMINI.md differ in name and loading). The substrate's "sentinel" file must be named per vendor; that is a per-vendor port, not byte-identical. Fix: default to the neutral harness and make own CLIs an E2E-0 failure condition, or register the per-vendor port and its review.

11. Phase 1 as a build may differ by arm in repository state (MINOR). Section 4. Substrate arms start from an installed substrate, then build; the spec cascade is generated "from the specification only" so N+S has a pre-decomposed spec index the other arms lack. That is the treatment, but it also gives S arms free spec work (setup cost counts it, ok) and changes what P-ACC phase 1 measures. Declare it.

12. Co-primary choice rests on the "complete spec" limit (MINOR). Section 12 notes the direction is unknown. The prior in section 1 ("substrate keeps a project correct") is stated for a complete spec, where the cascade adds little; the stated prior is not the likely effect. State the prior consistent with that.

## REVIEW-SURFACE-SPEC

13. Recall measurement is partly circular (MAJOR). Section 8. Instance classes come from the "human-read taxonomy" built by the same people, and several rules (S2, S3, S8) detect the very mutations authors of "injected defects" naturally write (suppression markers, deleted tests). Location recall at 0.80 on mechanical classes is nearly guaranteed. Freezing the rules before instance authoring helps only if authors never read the spec; they will, since the spec lists the patterns. Fix: authors work from a taxonomy that does not include the rule list; add instances authored by an independent person who has not seen the spec; report recall only on the held-out E2E-1 escapes as the primary figure.

14. Location recall can match for the wrong reason, and S1/S2/S11 make coverage trivial (MINOR). Any item on the same file counts. A tool flagging whole files (S11, S7 which flags every changed production file without a criterion index) covers everything. Fix: exclude SHOULD-only coverage from the headline, use line overlap at a stated granularity, and report recall with S7 and S11 disabled.

15. Not all rules are deterministic as written (MINOR). S3 "direction" depends on a declared format; S8 co-change heuristic ("expected value edited") needs a parser per framework; S6 "without any reference to a declared authorization helper in the same file" needs route detection per stack; S9 entropy threshold is a parameter. The determinism claim holds for the code, but testability for each rule requires per-stack fixtures not yet listed. Fix: list, for each rule, the exact detection input and the stacks supported, and mark unsupported ones as "not covered" in the output rather than silent.

16. The "escape-conditioned" view is conditioned on the nets of the same study (MINOR). Section 8.6. Escapes depend on which nets the E2E-1 repositories had; in substrate arms the tool's S2/S3 duplicates the gates. Fix: report the escape-conditioned view per arm and state it applies to those nets only.
