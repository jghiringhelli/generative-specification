# §VI.G — Twin studies: TX and SX (v0.3, compact; full text in `supplement/S2-twin-studies-full.md`)

### G. Behavior-preserving twin studies (twin comparisons, exploratory)

**TX (organization).** One representative undisciplined generation of the Conduit backend, a single 489-line route file with direct database access and no interfaces, was frozen as twin M and refactored by an executor into a behavior-preserving disciplined twin D (layered domain, application and infrastructure, repository interfaces, small units). A shared 13-file conformance suite passed identically on both, so they differ only in structure. Three findings, each bounded. (1) At fixed content, layering alone did not lower a stateless reader's cold-read cost: median read breadth was 5 files on D against 4 on M (k = 5), because one concern is spread across several small files. (2) Adding an authored sentinel to each twin drove exploratory search to zero on both; the read economy belongs to the authored map and not to layering. (3) Given a cross-cutting change on a small local model, the undisciplined twin was regenerated truncated (two of eight route handlers kept, still compiling, because untyped code carries no contract to violate) while the disciplined twin's small units regenerated whole and its type contracts turned the same model's error into a compile failure; a capable model showed no difference. One system, one small and one capable model: the mechanism is demonstrated and no effect size is estimated.

**SX (surface).** SX holds organization roughly fixed and varies content quality. A clean disciplined backend was compared with a behavior-preserving twin degraded to the industry-average state of a real project, calibrated to published norms on eight dimensions (about 13% live duplication, a few functions at cyclomatic complexity 20 to 40, about 17% dead code, about 38% coverage, mixed patterns, year-stale dependencies); both pass the same oracle 13 of 13. The task adds a computed field to every article response: one edit against the clean twin's centralized builder, five live duplicated copies on the degraded twin. Runs are agentic on one frontier model (`claude-sonnet-4-5`), n = 2 per cell, under a three-level sentinel ablation. With the map on both twins the degraded twin still cost about 2.4 times the tokens and 3.5 times the edits (7 versus 2), because the change must reach five copies; the map cut localization tokens about threefold on the degraded twin but removed none of the surface cost. A no-map condition was high variance even on the clean twin (2 edits in one run, 11 in another). Coherence held on all runs: the frontier model paid the surcharge instead of dropping a copy.

Together: reorganizing at fixed content does not cheapen reading, de-inflating does, and the navigation lever (the sentinel) and the bounding lever (removing duplicated and dead surface) are separable. SX is n = 2 on one benchmark and one model, and its weak-model coherence-failure arm is not run.
