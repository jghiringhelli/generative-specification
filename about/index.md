# About

Generative Specification is an open method for working with AI coding assistants, developed by J.C. Ghiringhelli. This site is its open home: the lessons, the models and equations, the papers and the evidence.

## Licence and citation

The content is distributed under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). To cite the archived preprint:

```
Ghiringhelli, J. C. (2026). Generative Specification: A Discipline of Derivability
for the Stateless Reader. Zenodo (archived preprint, July 2026).
https://doi.org/10.5281/zenodo.21726017
```

A revised base paper is in preparation; see [Evidence and papers](/evidence/) for the current plan.

## Contribute

The [gate library](/quality-gates/) is community-maintained: each gate is one YAML file mapped to one of the seven properties, and anyone can propose one by pull request. See [how to contribute a gate](/quality-gates/CONTRIBUTING.html) and the [gate schema](https://github.com/jghiringhelli/generative-specification/blob/main/quality-gates/schema.yaml).

Independent replications of the experiments, including null results, are also welcome by pull request. See [how to replicate an experiment](/docs/white-paper/EXPERIMENT-PUBLISHING-PLAYBOOK.html).

## Community convergence

When a practitioner community contributes to a shared method under quality gates, the specification floor across the domains it governs can rise and cannot retreat while the gates hold. This is a design intent for the library, argued in the Compendium; it is not a measured result.

## Tools

[ForgeCraft](https://github.com/jghiringhelli/forgecraft-mcp) is the earlier tool that implemented the method. It is deprecated: the [Practice](/practice/) guides are the tool-free versions, written as prompts you paste into any assistant. The [workflow recipes](/docs/recipes/) still describe the ForgeCraft tool calls.
